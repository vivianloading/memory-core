# HOME Wake Issuance v0.1 — Runtime-Bound Producer Proof

**Status:** DRAFT ENGINEERING / AUTHORITY BOUNDARY; synthetic/local only; no
renderer; no model delivery; real personal data CLOSED.

Issue: #63

## 1. Purpose

Wake Packet v0.1 established what HOME may safely carry.

Wake Issuance v0.1 answers a different question:

> **Did this exact Wake artifact actually come from canonical HOME state through
> the live HOME runtime, rather than from caller-manufactured typed objects?**

The two layers deliberately remain separate.

A bare `WakePacket` is still typed semantic data with:

`input_trust = typed_caller_input`

It does not become a credential.

Wake Issuance wraps an exact packet and exact assembly receipt with process-local
live proof:

`canonical HOME state -> WakeIssuanceAuthority -> IssuedWakePacket`

## 2. What the caller may request

The issuance API accepts one semantic request input:

- `episode_id`.

The caller does **not** provide:

- `EpisodeRecord`;
- `RoomAttachmentResolution`;
- continuity edges;
- `CurrentResolvedView`;
- packet `as_of`;
- packet `wake_id`;
- an issuance receipt.

Those are obtained or generated by the issuer.

This is the first boundary that distinguishes “typed shape” from “canonical live
producer”.

## 3. One coherent database snapshot

Living and Current state live in the same canonical HOME SQLite database.

Wake issuance opens one Current Resolver read connection. That connection is
already:

- read-only through SQLite `query_only`;
- inside one active `BEGIN` read transaction;
- pinned to the resolver's canonical database path.

The caller-owned `LivingStore` is binding evidence only. Operational Living
reads use a fresh base `LivingStore` pinned to the already-resolved canonical
database path, and the issuer calls the base Living/Current implementations for
the new issuance path rather than trusting caller-replaced instance methods.

The issuer validates Living integrity on that same connection, then reads:

- the requested Episode;
- continuity edges;
- that Episode's Room attachment history;
- attached Room Current through
  `CurrentResolver._resolve_owner_in_connection(...)`.

No second Living or Current connection is opened for the issuance operation.

This matters because:

> two individually valid snapshots do not prove one coherent “now”.

If concurrent state changes race the read cut, the issuance operation must remain
on the already-pinned SQLite snapshot or fail closed. It must not combine old
Living with new Current (or the reverse).

## 4. Time cut

The authority is opened with an injected **runtime operation clock**.

This clock is an issuer dependency, not a caller-selected historical query
parameter. `issue(...)` accepts no `as_of` argument. Wake Issuance v0.1 does
not claim historical Living-route reconstruction.

Each `issue(...)` operation calls that clock exactly once, before canonical
reads begin.

The returned value must be one timezone-aware `datetime`.

That exact represented instant becomes:

- Current Resolver `as_of`;
- Wake Packet `as_of`;
- Wake Assembly Receipt `as_of`;
- Wake Issuance Receipt `as_of`.

Lower layers do not call ambient wall clock.

A naive or non-datetime clock result fails before canonical reads.

## 5. Current admission remains live and process-local

Wake issuance does not weaken Current Resolver.

For an attached Room, the issuer invokes the existing live
`CurrentResolver` on the same snapshot connection.

That resolver still requires the exact live
`CurrentAdmissionAuthority` receipts associated with admitted Current effects.

If durable Current/admission rows exist without the required live receipts, the
result remains:

`ADMISSION_PROOF_UNAVAILABLE`

Wake Packet then carries its existing partial/withheld Room Now semantics.

Durable audit is not promoted into operational authority merely because Wake
would otherwise be sparse.

## 6. Process-local issuance proof

A successful issuance returns:

`IssuedWakePacket(packet, assembly_receipt, issuance_receipt)`

The `WakeIssuanceReceipt` binds:

- issuance version;
- random issuance id;
- exact live authority id;
- HOME process instance id;
- canonical database binding digest;
- Wake id;
- Episode id;
- exact `as_of`;
- deterministic digest of the exact Wake Packet;
- deterministic digest of the exact Wake Assembly Receipt.

Receipt construction requires a private package marker.

The issuing authority also registers the **exact receipt object** in an
instance-owned process-local registry guarded by a lock.

That instance-owned registry is not treated as sufficient proof of the issuer
object itself. A separate module-level process-local **origin registry** binds
each random `authority_id` to the exact authority object that completed live
construction. This prevents shallow-copy / state-alias objects from inheriting
the original registry, identifiers, locks, and receipts and then claiming to be
the originating issuer.

Live verification requires:

- the authority object itself is the exact origin object registered for its
  `authority_id`;
- the exact authority instance that registered the receipt;
- the exact HOME process incarnation;
- unchanged canonical database binding;
- unchanged receipt fingerprint;
- unchanged packet digest;
- unchanged assembly-receipt digest.

A second Wake issuance authority opened over the same database is intentionally
a distinct issuer and cannot verify the first issuer's receipt.

## 7. Database binding

The authority binds to one resolved canonical database path.

That raw machine path is **not** put into the issuance artifact.

The receipt carries a SHA-256 binding digest instead.

This digest is operational/process-local proof metadata, not semantic identity,
Room identity, subject identity, or portable HOME history.

If the caller-owned Living Store path or bound Current Resolver path drifts after
opening, the authority fails closed.

## 8. Artifact digest

Wake Issuance computes deterministic SHA-256 digests over the typed dataclass
structure.

The canonical digest representation preserves:

- dataclass type identity;
- dataclass field names and order;
- enum type + value;
- timezone-aware datetime textual representation;
- exact timedelta microseconds;
- tuple structure;
- primitive values.

Packet and AssemblyReceipt digests bind every dataclass field in those
artifacts. The issuance-receipt registry fingerprint is built from an explicit
receipt-field tuple; its private construction marker is not treated as semantic
artifact content.

The digest is not a cryptographic signature or external authenticity proof. Its
purpose is exact process-local artifact binding: a receipt registered by one
live authority cannot be paired with a modified packet or modified assembly
receipt and still verify.

## 9. Read-only boundary

Wake Issuance creates no durable credential row.

Issuance:

- does not write canonical HOME state;
- does not persist an issuance capability;
- does not create restart-safe authority;
- does not turn an audit row into a credential.

A later durable issuance audit may be useful, but if added it must remain audit
provenance only unless a separate restart-safe authority design is approved.

## 10. What issuance proof means

An issuance receipt proves only:

> this exact Packet + AssemblyReceipt pair was produced from one canonical HOME
> read snapshot by this exact live WakeIssuanceAuthority in this HOME process
> incarnation.

It does **not** prove or grant:

- first-person speech authority;
- instruction authority;
- identity-continuity claim authority;
- relationship-claim authority;
- model-delivery authority;
- memory-write/re-ingestion authority.

Those six axes remain `none` inside Wake Packet v0.1.

Producer proof is not speech authority.

## 11. Route behavior

For an attached Episode:

- Living resolves the canonical Room route on the shared snapshot;
- Current Resolver resolves that Room on the same shared snapshot;
- ordinary Wake Packet assembly receives the resolved Current view.

For unattached or unresolved Episode route:

- no Room Current lookup is invented;
- Wake Packet preserves explicit Room Now unavailable semantics.

Wake Issuance does not change the v0.1 fixed-layer producer reality:

- Map: available from canonical Living;
- Shared Now: CLOSED;
- Room Now: canonical live Current when attached;
- Recent Life: UNAVAILABLE;
- Nearby Doors: UNAVAILABLE.

## 12. Explicit limitation

The returned `IssuedWakePacket` is stronger than a bare `WakePacket` only in
producer provenance.

A valid issuance receipt proves **what happened at its issuance snapshot**. It
does not claim that no canonical state, suppression, route, or Current value
changed after that snapshot.

Therefore an issuance receipt is not a timeless “still current” credential.
Future model delivery must obtain issuance as part of its own fresh delivery
operation; it must not treat an old retained issuance as proof of present
freshness. v0.1 deliberately does not invent a time-to-live or durable freshness
epoch here.


It is still **not renderer input authorization**.

A future Wake renderer/delivery slice should require a live
`WakeIssuanceAuthority.require_live_issuance(...)` check before using the
Packet, and must independently enforce the carriage-vs-speech boundary.

That future renderer must not consume `WakeAssemblyReceipt` as a second model
context channel.

## 13. Initial adversarial contract

v0.1 must fail closed against at least:

- caller-supplied fake Episode/route/Current typed inputs;
- Living Store and Current Resolver bound to different databases;
- naive clock;
- more than one clock read per issuance;
- different SQLite connections for Living and Current within one issuance;
- a caller-owned Living instance method being substituted as the canonical producer;
- a concurrent route write tearing one issuance across pre/post-write state;
- caller-minted receipt;
- foreign-authority receipt replay;
- changed canonical database binding;
- nested Packet mutation after issuance;
- AssemblyReceipt mutation after issuance;
- wake/episode/as-of rebinding;
- durable Current rows without live admission proof;
- model/renderer capability appearing in the issued wrapper.

Positive controls include:

- attached canonical Episode with live admitted Current;
- unattached canonical Episode;
- untouched issuance verified by its exact live authority;
- issuance causing zero canonical database mutation.

## 14. Non-claims

Wake Issuance v0.1 does not establish:

- renderer safety;
- model/prompt delivery;
- restart-safe issuance credentials;
- producer proof across HOME process restart;
- Shared governance;
- Recent Life selection;
- Nearby Doors navigation;
- relationship Current;
- restore/unsuppress;
- identity continuity;
- real-data readiness;
- production readiness;
- merge authorization.

## 16. Independent review #65 — issuer-origin identity NO-GO

Independent review #65 returned **FAIL / NO-GO** on exact head
`941b11af3bcddee3257943b6c40745747697db4f`.

The reviewer independently confirmed multiple intended boundaries, including
separate-authority receipt rejection, marker-retaining receipt-copy rejection,
artifact digest mutation rejection, read-only issuance, and the typed-caller /
NONE-authority distinctions.

The blocking contract gap was narrower and deeper:

> receipt-object identity was bound, but the authority object's own originating
> identity was only self-attested by its copied instance state.

A shallow copy or manual state alias could in principle preserve the
instance-owned receipt registry, authority id, process id, DB binding, locks,
and fingerprints. The prior implementation had no independent witness proving
that the verifier object itself was the authority object that originally
completed construction.

The remediation adds a separate process-local origin registry:

`authority_id -> exact WakeIssuanceAuthority object`

Registration occurs only at the end of valid authority construction. Every
`issue(...)` and `require_live_issuance(...)` path reaches
`_assert_live_binding()`, which now requires the origin registry entry to be
object-identical to `self`.

Therefore:

- a separately opened authority still has a different authority id;
- a shallow copy preserving all instance state is rejected;
- an `object.__new__` + `__dict__` state alias is rejected;
- copied receipt registries and locks do not become issuer-origin proof.

The origin registry is process-local runtime state, not durable authority,
semantic identity, Room identity, or restart-safe credential.

The origin witness also retains the exact opening-bound runtime dependencies:
the caller-binding LivingStore, internal canonical LivingStore, CurrentResolver,
clock object, receipt registry/guard, canonical DB binding, and HOME process
instance. Live binding rejects substitution of those objects on the original
authority after opening. This is intentionally object/dependency identity, not
a claim that a mutable clock's future return values are themselves frozen.

#65 remains permanently scoped to its failed exact SHA. A later head requires a
fresh exact-SHA independent review, including the bounded sweep #65 did not
reach.

## 17. Independent review #66 — operation-receiver substitution NO-GO

Independent review #66 returned **FAIL / NO-GO** on exact head
`1529219d06f9217d67346a9e51b1ede7a48b014a`.

The origin registry added after #65 correctly rejected ordinary shallow copies,
manual `__dict__` aliases, and separately opened authorities.

The remaining blocker was Python method dispatch at the public operation
boundary. `issue(...)` and `require_live_issuance(...)` called
`self._assert_live_binding()`. A non-origin alias could therefore attach the
genuine bound checker of the original authority as its own instance attribute:

`alias._assert_live_binding = original._assert_live_binding`

The check then ran with the original authority as its receiver while the public
operation continued with the alias as its receiver. The independent origin
registry was correct; the operation checked the wrong object.

The remediation removes instance-dispatch authority from this security-critical
edge. All public issuance entry checks now call:

`WakeIssuanceAuthority._assert_live_binding(self)`

The operation receiver is therefore supplied explicitly to the base-class
checker and cannot be substituted by an instance attribute or bound method.

The same rule applies to the second live-binding check before receipt minting.

Regression coverage includes both:

- `copy.copy(authority)` plus the original bound checker;
- `object.__new__ + __dict__` state alias plus the original bound checker.

Both are invoked through the genuine base public methods with the alias
explicitly supplied as receiver and must fail before issuance/verification can
continue.

The #66 reviewer completed substantial bounded coverage before confirming this
supplementary blocker. That passing breadth remains evidence scoped to the failed
SHA and does not extend automatically to a later head.

#66 remains permanently scoped to its failed exact SHA. A later head requires a
fresh exact-SHA review.

### Author-side same-family hardening after #66

After fixing operation-receiver dispatch, author self-review extended the same
origin invariant to the original authority object's opening-bound dependencies.

The process-local origin registry now stores a frozen witness of the exact
objects/values that defined the authority at construction:

- caller-binding LivingStore;
- internal canonical LivingStore;
- CurrentResolver;
- clock object;
- receipt registry and lock;
- canonical DB path/digest;
- HOME process instance.

`_assert_live_binding()` requires the current authority state to match that
independent opening witness before any issue/verify operation proceeds.

This closes the adjacent case “the object is still the original `self`, but
its runtime producer dependencies were replaced after opening.”

The witness binds dependency identity, not immutable future clock output.
